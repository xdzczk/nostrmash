# account store context — sqlc pilot

This bounded context is the project's **sqlc pilot**. The single-table
`account_states` / `account_state_transitions` statements are generated by
[sqlc](https://sqlc.dev) from:

- schema: [`migrations/000052_account_states.sql`](../../../migrations/000052_account_states.sql)
- queries: [`queries/account.sql`](queries/account.sql)
- config: [`sqlc.yaml`](../../../sqlc.yaml) (repo root)

Generated code lives in [`accountdb/`](accountdb) and is committed. Regenerate
with `make sqlc` and verify drift with `make sqlc-check` (wired into `make ci`).

## What is and isn't generated

`account.go` remains the public surface: it keeps pubkey normalization, the
`nil`-store guards, transaction orchestration, and the domain row/param types.
Each exported method delegates the actual SQL to `*accountdb.Queries` bound to
the pool or an in-flight `pgx.Tx` (`accountdb.New(tx)`).

Two statements stay hand-written on purpose:

- `BatchIncrementAccountObservations` — uses a multi-column `unnest($1,$2)`
  upsert that sqlc's static analyzer cannot type.
- `ListAccountSignalsForRecompute` — joins into the trust and profile
  projections, which belong to other bounded contexts and are outside this
  context's sqlc schema.

## Verdict criteria (should we extend sqlc to other contexts?)

Evaluate the pilot against these before adopting sqlc more broadly:

1. **Drift safety net earns its keep** — `sqlc-check` catches at least one real
   query/schema mismatch that a reviewer would otherwise miss, without frequent
   false positives.
2. **Type mapping stays thin** — the pgtype↔domain conversion helpers do not
   grow faster than the SQL they replace. If wrappers become mostly conversion
   glue, sqlc is a net loss for that context.
3. **Analyzer coverage** — the context's real queries are expressible; if most
   need hand-written escapes (multi-array `unnest`, cross-context joins,
   dynamic SQL), sqlc buys little there.
4. **Build/CI cost** — the `go run sqlc diff` step stays acceptable in CI.

Extending the pilot to another context (`trust`, `read`, `retention`, …) is a
deliberate, separate decision made only after this context's verdict is
positive on the criteria above.
